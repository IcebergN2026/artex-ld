任务轨迹可视化方案 Demo

模拟数据:一次外网渗透任务 · mainagent / planner / review / work#1 / work#2 · 数据结构与 activity 表 kind 对齐

① 泳道甘特图(Swimlane Gantt)

形态:每个 agent 一条横向泳道,X 轴为时间;瞬时步骤(思考/文本/意图)为圆点,工具调用(tool_use→tool_result)为跨时长条,直观呈现并行与空闲。

优势:一眼看出谁在和谁并行、哪里在空转、哪个 agent 是瓶颈;运行中右侧持续增长,天然支持"钉最新"。

代价:不展示正文,需点击/悬停看摘要,详情可跳回现有 Transcript 对应 seq(建议作现有时间线的「概览模式」切换,而非替代)。

② 工具调用瀑布图(Waterfall)

形态:仿浏览器 DevTools 网络面板,每次工具调用一行,条长=执行耗时,按开始时间排列,标注工具名与耗时。

优势:专治"任务为什么慢"——nmap 全端口扫、爆破等长耗时调用立刻凸显;适合做性能/成本分析视图。

代价:只看工具调用,思考与对话被过滤;是轨迹页的「耗时分析」子视图。

③ Agent 协作流图(Collaboration Flow)

形态:节点=agent(大小∝步数),有向边=驱动关系(用户→主 Agent→规划→审核→Worker;Worker→规划为结果回流),边宽∝事件数。

优势:10 秒讲清"这个任务里谁驱动谁、审核拦了几次、哪个 Worker 干得最多",适合任务复盘页顶部。

代价:静态聚合视图,无时间维度;与①④互补。

④ 缩略导航时间线(Minimap)

形态:左侧紧凑文字时间线(每步一行),右侧 72px 密度缩略条——每步一个 3px 色块(颜色=步骤类型),蓝框指示当前视口,点击缩略条跳转。

优势:改动最小(在现有 Transcript 旁加一条)、长任务(数百步)导航能力质变;色块分布本身即"轨迹指纹"(大段紫色=长推理,密集蓝点=工具风暴)。

代价:导航增强而非新叙事;推荐作为首期落地方案。

⑤ 统计仪表盘(Summary Dashboard)

形态:KPI 卡片(总步数/工具调用/耗时/token)+ 每 agent 步数条 + 步骤类型分布环图 + 高频工具 Top N。

优势:面向管理者与成本视角:token 花了多少、哪个工具被滥用、agent 负载是否均衡;全部可由现有 activity/usage 行本地聚合,零后端改动。

代价:无叙事性;适合作为轨迹页顶部可折叠的「概览条」。
